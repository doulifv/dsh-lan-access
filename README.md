# dsh-lan-access

让 **DeepSeek Harness 桌面端** 把内置 GUI 通过局域网暴露出来，这样你可以用手机在同一 Wi-Fi 下访问它。

本插件在你电脑上额外开一个监听 `0.0.0.0` 的反向代理，把本机的 loopback 服务（`127.0.0.1:19387`）转发到局域网。内置的 web 服务原本只监听回环地址，本插件利用"插件可自己开监听、不受 `--host 0.0.0.0` 限制"这一点实现局域网访问，同时把请求头的 `Host` 重写为回环地址以通过内置的信任校验。

---

## ⚠️ 安全须知（务必先读）

- **明文 HTTP**：手机与电脑之间的流量**未加密**，同一局域网内的任何设备都能嗅探。请只在你信任的网络（自家 Wi-Fi）使用。
- **残余风险（务必知道）**：因为流量不加密，同一局域网内的攻击者可以**嗅探到会话 Cookie 并重放**，从而在 Cookie 有效期内（12 小时）冒充你的手机访问桌面端。**本插件无法消除这个风险**——明文 HTTP 上不存在安全的 Cookie。需要真正的加密，请停用本代理改用 **SSH 端口转发**，或改用其它带 TLS 的反向代理。
- **访问门 = 签名会话 Cookie**：通过令牌门之后，代理会下发一个 **HMAC-SHA256 签名的会话 Cookie**（名为 `dsh_lan`，有效期 12 小时，带 `HttpOnly` + `SameSite=Lax`；因为是明文 HTTP，所以**不加 `Secure`**）。未通过门一律 `401`。签名密钥由 `accessToken` 派生。
- **令牌只出现一次**：首次访问请打开一次性登录链接 `http://<局域网IP>:<lanPort>/?lt=<令牌>&token=<dsh启动令牌>`。代理校验 `lt` 后会把请求**转发给后端**（让后端消费 `token` 并下发它自己的 Cookie），随后 **302 跳转到同时去掉 `lt` 与 `token` 的干净 URL**，并在同一个响应里下发本插件的签名 Cookie；两个一次性令牌都不会停留在地址栏或浏览器历史里。
- **轮换令牌 = 全体下线**：因为签名密钥由 `accessToken` 派生，所以管理页点 **轮换令牌** 会让**所有已授权设备立即失效**。怀疑令牌泄漏或手机丢失时，这是最快的止损手段。
- **不要关掉令牌门**：配置里 `requireToken: false` 会让代理对局域网**完全开放**，任何人都能直接操作你的桌面端（**可执行代码**）。除非你清楚后果，否则保持开启。
- **令牌是明文存活的**：`/__lanapi/status` 会返回**完整明文令牌**（这是刻意的，供管理页生成手机链接），本机上的任何进程都能读到；代理启动日志里也会出现手机链接。**本机被入侵 = 令牌泄漏**，这一点无法通过局域网侧加固解决。
- **管理页没有 CSP/防嵌入头、`?lt=` 没有频率限制、WebSocket 升级不校验 `Origin`**：这三项是当前版本已知的剩余弱点，详见审计报告 §3。它们的**影响面都在本机或已授权设备**上，不改变"只连信任网络"这条底线。

## 管理页与控制接口不外泄

- 管理页 `/__lan-access` 与控制 API `/__lanapi/*` 注册在本机内置 webServer 上（**默认只绑定回环地址**，因此本机访问走 `127.0.0.1`）。
- 除此之外，代理层还会对它们做二次拦截：从**局域网**一侧访问 `/__lan-access` 或 `/__lanapi/*`，代理会**直接返回 `404`**，不会转发到后端。
- 因此局域网内的设备**既打不开管理页，也调不动控制接口**，也不会通过这些路径读到明文令牌。管理页只应在本机打开：`http://127.0.0.1:19387/__lan-access`。

## 安装

两种方式任选其一。

### 方式 A：用插件面板安装（推荐）

1. 打开桌面端 → 设置 → **Plugins（插件）** 面板。
2. 选择 **Add plugin（添加插件）**，填入本目录的**绝对路径**（即本 README 所在目录，例如 `I:\dsh-lan-access v0.1.13`），或指向打包好的 tarball / Git 地址。
3. 安装后确认它在 `desktop` profile 下被启用。

> 路径请以**你自己机器上的实际位置**为准；目录名里的空格是允许的，但记得在命令行里加引号。

### 方式 B：命令行 `dsh plugin`（或 `plugin_manager`）

```bash
# 用 dsh plugin 把本地目录加入 desktop profile（注意引号）
dsh plugin --profile desktop add "<本目录的绝对路径>"
```

等价地，也可以在对话里用 `plugin_manager` 工具：`action: install_bundle`，`target` 设为该目录的绝对路径。
安装后插件会出现在 `$DSH_HOME/profiles/desktop/node_modules/dsh-lan-access`，并在 `cordis.patch.yml` 中插入一条 `dsh-lan-access` 配置项。

## 启用与配置

启用/停用由桌面 profile 的 `cordis.patch.yml` 控制（与 HMR 同机制，改完即时生效）。

在 `cordis.patch.yml` 里加入（如没有该文件则在 `profiles/desktop/` 下新建）：

```yaml
dsh-lan-access:
  enabled: true
  config:
    lanPort: 19193        # 局域网监听端口（手机访问这个端口）
    requireToken: true    # 必须通过 ?lt= 一次性令牌换取签名 Cookie
    autoStart: true       # 桌面端启动时自动开代理（最多等 60 秒回环端口就绪）
    # accessToken: "..."  # 不填则每次启动随机生成；填了则固定
```

- `enabled` 控制插件是否加载。
- `config` 是传给插件 `apply(ctx, config)` 的配置。
- `accessToken` 留空时每次启动随机生成（48 位十六进制）；填了则固定，方便手机长期免登录。**短于 16 位只会在日志里警告，不会被替换**，但请不要这么用。
- `lanPort` 非法（非 1–65535 整数）时回退为 `19193`，并在日志里警告。
- **`lanPort` 只能在配置里改**（改完需重载插件）；管理页**没有**改端口的功能，`/__lanapi/port` 路由也已移除。端口属于启动期设置，运行中热切换在 Windows 上不可靠（`server.close()` 只停止接受连接，keep-alive 句柄可能仍占着端口），因此该功能被整体删除而不是继续修补。
- `autoStart: true` 时，若桌面端启动后回环端口还没就绪，插件会**轮询等待最多 60 秒**再启动，不会像早期版本那样直接放弃。

## 使用（无需重启 DeepSeek Harness）

启动、停止、轮换令牌都**不需要重启 DeepSeek Harness**（改 `lanPort` 需要重载插件）。

1. 桌面端启动后，在本机浏览器打开管理页：

   ```
   http://127.0.0.1:19387/__lan-access
   ```

   （`19387` 是内置 web 端口，若不同请自行改成实际端口；管理页默认只在 `127.0.0.1` 提供，局域网访问会得到 `404`。）

   > 桌面端「**设置**」对话框的左侧导航里会多出一项「**局域网访问**」，
   > 里面有「打开管理面板」按钮和面板地址，不必再手敲 URL。
   > 该入口由客户端 bundle（`lib/client.js`）通过宿主的 `settings.section` 槽位注册；
   > 若宿主版本不认识该槽位，入口会**静默隐藏**，宿主设置界面不受影响，代理功能也完全不受影响。
   > 注意面板地址固定为 `127.0.0.1:19387`。

2. 点 **启动代理**。状态卡片会显示监听地址、本机局域网 IP，以及**错误**提示（若有）。

   - 若 `autoStart: true`，桌面端启动后代理会**自动拉起**：它会先等待内置 web 端口就绪再开始监听，无需手动点击，也无需重启。
   - 若某个端口绑定失败（Windows 常见：`EACCES` 端口被保留 / `EADDRINUSE` 被占用），状态卡片会直接显示原因与建议。处理办法是**修改配置里的 `lanPort` 后重载插件**——管理页不再提供改端口入口。
   - 停止会**尽力真正释放监听 socket**（关闭所有连接 + 主动销毁 idle keep-alive 连接 + 轮询探测端口是否空闲后再重绑）。探测有约 1.2–1.5 秒预算，因此这是**尽力而为**而非绝对保证；极端情况下（系统迟迟不回收句柄）仍可能短暂 `EADDRINUSE`，再点一次即可。
   - 插件重载时，新实例会**接管并停掉旧实例**（而不是变成 no-op），并且会等待旧实例的端口真正释放后再绑定。
   - 操作按钮有 **12 秒**前端超时：若一次"停止+启动"较慢（等待旧端口释放、回环端口未就绪），卡片可能先报超时而后台其实已成功——**以状态卡片的实际状态为准**，或点"刷新"。

3. 卡片会列出**每个局域网 IP 一条**手机登录链接（电脑常有多张网卡，手机只能连到同网段那个 IP）。把对应网段那一条发到手机（微信/邮件/扫码），在手机浏览器打开一次：

   - 链接形如 `http://<局域网IP>:19193/?lt=<令牌>&token=<dsh启动令牌>`，两个都是一次性凭证；
   - 代理校验 `lt` 通过后会把请求**转发给后端**（转发时剥掉 `lt`，保留 `token`），让后端消费启动令牌并下发它自己的 Cookie；随后 **302 跳转到同时去掉 `lt` 与 `token` 的干净 URL**，并在同一响应里下发签名会话 Cookie（`dsh_lan`，12 小时）；
   - 之后手机凭该 Cookie 正常访问，地址栏里不再有令牌。
   - **务必用"点击"或"复制"拿到链接，不要在别处缓存它**：`token` 是一次性的，
     聊天软件的链接预览、点第二次、或页面渲染后放久了，都会让它变成废票。
     管理页的"点击"和"复制"按钮都会在**动作发生的瞬间**重新取一条最新链接，所以不会再点到旧票。
   - 万一点到废票，页面会明确告诉你"登录令牌已失效"并给出解决办法（回管理页点"刷新"再点新链接），
     而不是丢一句 `dsh web authentication required`。宿主日志里也会记一条对应告警（不含令牌值）。
   - 若代理**已停止**，卡片会显示"(代理未运行——请先点启动代理)"，因为手机链接只在代理运行时才有意义。

4. 手机之后访问：`http://<你电脑的局域网IP>:19193/`（例如 `http://192.168.1.50:19193/`）。

> 提示：每次桌面端重启若未固定 `accessToken`，令牌会变，需要重新从管理页拿手机登录链接给手机再点一次。固定 `accessToken` 可避免。
>
> 提示：局域网 IP 建议在路由器上给电脑绑定静态地址，否则 IP 变化后旧链接与已打开的页面都会失效（手机凭 Cookie 走的是新 IP，但书签会失效）。

## 工作原理（简述）

- 插件注入 `webServer` 与 `connection` 两个服务。
- 自己用 `node:http` 在 `0.0.0.0:<lanPort>` 开一个代理服务器，把所有请求转发到
  `127.0.0.1:<webServer.port>`，并**重写 `Host` 头为回环地址**——内置信任校验据此放行。
  后端端口**按每个请求实时解析**，因此内置 web 端口变化后无需重启。
- 因为代理绑定的是 `0.0.0.0`，浏览器会送出 `Origin/Referer = http://<局域网IP>:<lanPort>` 与
  `sec-fetch-site: cross-site`，这些会被内置 `/api` 信任围栏拒绝；代理会**一并重写**这几个头为回环地址，
  否则手机上的目录选择器、插件页、RPC 全部会 403。
- 转发时会**剥离 hop-by-hop 头**（`Connection`、`Proxy-Connection`、`Keep-Alive`、`Transfer-Encoding` 等），
  并补上 `X-Forwarded-For`（**覆盖**客户端伪造的同名头）与 `Via`。
- 访问门：`?lt=<accessToken>`（一次性）或已存在的
  **HMAC 签名会话 Cookie** 才放行；否则 `401`。签名密钥由 `accessToken` 派生，所以轮换令牌会让所有设备下线。
  手机链接里还带着第二个一次性凭证 `&token=<dsh 启动令牌>`：**只有后端**能把它换成自己的 Cookie。
  因此 `?lt=` 校验通过后，代理**会把这次请求转发给后端**（转发时剥掉 `lt`，只留 `token`），
  拿到后端的 `Set-Cookie` 后再**连同本插件自己的会话 Cookie 一起**回一个 302，
  Location 是**同时去掉 `lt` 和 `token`** 的干净地址。
  —— 早先的实现在这一步直接返回 302、根本不联系后端，导致后端的启动令牌从未被消费。
- **转给后端的请求头里，Fetch Metadata 会被无条件规范化**：`sec-fetch-site` 一律置为
  `same-origin`，非 loopback 的 `origin` 直接**删除**。
  原因是管理页从 `http://127.0.0.1:19387/__lan-access` 提供，而手机链接指向
  `http://<局域网IP>:19193/?lt=…`——**点击**它是一次**跨源顶层导航**，浏览器会带
  `sec-fetch-site: cross-site`（通常还带 `origin`）；而**粘贴到地址栏**是用户直接发起的导航，
  **两个头都不带**。后端的守卫
  （与 `isTrustedRequest` 同构：`sec-fetch-site === 'cross-site'` 直接拒、`origin === undefined` 直接过）
  因此对**逐字节相同**的 URL 给出相反结果。
  这是"点击失败、粘贴成功"的根因；只在头存在时才改写（旧实现）会把这个跨源信号一路带给后端。
  `sec-fetch-mode` / `sec-fetch-dest` / `sec-fetch-user` 原样保留，
  因为后端靠它们判断"这是一次顶层页面加载"，启动令牌交换依赖这一点。
- **交换失败不再静默变 302**：后端若返回 ≥400 **或没有下发 `Set-Cookie`**，
  说明启动令牌是废票（一次性，可能已被链接预览/二次点击消费）。
  此时返回 **401 + 一页说明**（直接告诉用户回管理页刷新、用新链接），
  同时打一条**不含令牌值**的告警日志；
  而不是像以前那样回一个"代理门已通过、后端仍没认证"的 302，
  让用户再次看到那句无解的 `dsh web authentication required`。
- `/__lanapi/status` 的响应带 `cache-control: no-store`（它含明文访问令牌，不允许被缓存落盘）。
- WebSocket 升级（GUI 的实时连接）用裸 socket 双向桥接，只校验、不签发 Cookie（升级请求无法表达 302）。
- 管理页与所有控制接口（`/__lan-access`、`/__lanapi/*`）注册在 **loopback 的内置 webServer** 上；
  代理层对这两类路径再直接返回 `404`，绝不暴露到局域网。
- 改动类控制接口（`/start`、`/stop`、`/rotate`）带一个轻量 CSRF 守卫：带 `Origin` 的跨站请求会被拒。
- 手机登录链接用 `ctx.connection.authenticatedUrl(...)` 实时生成，无需读取任何文件里的密钥。
- 客户端半（`lib/client.js`）是一个 classic bundle，通过
  `window.__ModuleLoader__.load({ id, factory: (require) => ... })` 自我注册，
  返回的模块暴露 `inject: ['slots']` 与 `apply`；在 `apply(ctx)` 里经
  `ctx.inject(['slots'], (scope) => ...)` 拿到 `slots` 服务，再用
  `scope.slots.inject('settings.section', ...)` + `scope.slots.register({...})` 注册一个设置区块。
  区块渲染函数返回 **React 元素**（`react.createElement('div', { ref })`），
  命令式 DOM 在 `useEffect` 里挂到该 ref 上。React 由宿主经模块表注入
  （`require('react')`），所以本包**依然零 npm 依赖**。

## 局域网会话的功能边界（为什么手机上改不了模型/提供商）

在局域网地址（`http://<局域网IP>:<lanPort>`）打开一套带提供商目录的界面时，可能会看到：

```
加载提供商目录失败: settings are unavailable in this browser
```

**这不是本插件的 bug。** 我们已在宿主（`DeepSeek Harness` 本体）代码里定位到确切来源：

| 位置                                | 内容                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| `app.asar:482278`                   | 中文文案 `loadFailed: "加载提供商目录失败"`（英文版在 `:482162`） |
| `app.asar:480311`                   | `this.failLoad(generation, mirrored.error ?? "settings are unavailable in this browser");` |
| `app.asar:480299 / 480309`          | 先 `await this.describeFace.ensure()`，再 `getSnapshot()`，命中条件是 `view === undefined` |
| `app.asar:489680`                   | `const persistence = ctx.remote.$host.isLoopback ? "host" : "memory";` |
| `app.asar:489289 / 489297`          | 只有 `persistence === "host"` 才去读宿主设置；`memory` 时状态直接是 `unavailable` |
| `app.asar:370827`                   | `isLoopback` 的值来自 `pageLocation.hostname`，也就是**浏览器自己的 `window.location`** |
| `app.asar:374962 / 375020 / 388355` | 宿主文档明确写着：非 loopback 页面保留设置「仅当前进程」（即不予下发） |

链路是这样的：

1. 宿主按 **`ctx.remote.$host.isLoopback`** 决定要不要下发 Host 设置作用域（`:489680`）。
2. 而 `isLoopback` 是**浏览器端**按 `window.location.hostname` 算出来的（`:370827`），**不是**按服务端看到的 `Host` 头。
3. 本插件的代理只改了服务端那一侧（把 `Host` 重写成 `127.0.0.1` 以通过信任栅栏），**改不了浏览器自己的地址栏**——它仍然是 `http://<局域网IP>:19193`。
4. 于是客户端判定「非 loopback」→ 设置作用域被**故意扣住** → 依赖设置的提供商目录取不到值 → 报出上面那条消息。

宿主的这三处文档把动机说得很清楚：非 loopback 页面**无法落盘写设置**，所以宿主干脆不下发这个作用域。这是刻意的安全边界，不是疏漏。

也确认过没有干净的绕法：

- `trustedHosts`（`:371726`）只作用于**服务端** `/api` 信任栅栏（`isTrustedApiRequest`，`:371130`），**完全不参与**客户端 `isLoopback` 的计算。
- `window.location` 在现代浏览器里不可伪造（`configurable: false`），注入脚本也遮蔽不了。
- 在客户端强行把 `isLoopback` 改成 `true`，等于**伪造一个安全相关的事实**，还会连带影响语言偏好落盘、欢迎提示确认等一众分支，收益远小于风险。

> 这和我们之前修的 `SameSite` 问题**同源**：**请求头/响应头怎么改写，都改不了一个由浏览器自己决定的事实。**

**实用结论**：把局域网会话当作「**远程查看与对话终端**」。提供商/模型/偏好的**配置请在本机 `http://127.0.0.1:19387` 上完成**——那里 `isLoopback` 为真，设置作用域正常下发。配置保存后，局域网会话会读到宿主的当前值。

## 已知限制

- **仅明文 HTTP**，无 TLS（自签名 HTTPS 方案见审计报告第 4 节）。
- 管理页**不再显示掩码令牌，而是显示完整令牌**，便于手动抄写到手机；请勿在有他人旁观时打开管理页。
- **改端口必须改配置并重载插件**：运行中的“应用端口”功能已在 v0.1.10 整体删除（Windows 下不可靠），管理页也不再提供端口输入框。
- 会话 Cookie 未绑定 IP/端口/UA，12 小时内可重放；局域网嗅探者可冒充手机。
- `/__lanapi/status` 返回明文完整令牌；代理启动日志里也会出现手机链接。**本机不可信 = 令牌不可信。**
- 管理页无 CSP / 防嵌入头；`?lt=` 无失败频率限制；WebSocket 升级不校验 `Origin`。
- 局域网 IP 变化后，之前发出去的手机链接作废（Cookie 仍在 12 小时内有效）。
- 前端操作按钮 12 秒超时，慢启动场景可能"报超时但其实成功了"。
- 未固定 `accessToken` 时，每次启动令牌都会变。
- 设置里的「局域网访问」快捷入口**硬编码 `127.0.0.1:19387`**；DSH web 端口不同时该链接不可用（代理功能不受影响）。
- 客户端半依赖宿主的 `settings.section` 槽位；宿主版本过旧时入口静默隐藏。
- **局域网会话里「设置 → 模型/提供商」会加载失败**（提示 `加载提供商目录失败: settings are unavailable in this browser`）。这是宿主的设计限制，**不是本插件的缺陷，也无法在本插件内修复**。详见上文「局域网会话的功能边界」。

## 卸载

在插件面板里禁用/卸载 `dsh-lan-access`，或在 `cordis.patch.yml` 将其 `enabled` 设为 `false`。删除 `node_modules/dsh-lan-access` 目录即可完全移除。


**Uninstall:** disable/remove `dsh-lan-access` in the Plugins panel, or set `enabled: false` in
`cordis.patch.yml`; delete `node_modules/dsh-lan-access` to remove it completely.
